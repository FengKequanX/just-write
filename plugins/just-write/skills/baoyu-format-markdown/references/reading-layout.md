# 手机阅读排版规则

公众号与轮播共用以下内容规则，具体字体、字号和图片布局由各平台渲染器处理。

- **先组织段落，再增加装饰。** 一段表达一个完整意思；论点、依据、例子或话题明显转换时另起一段。不要每句话独立成段，也不要按固定字数机械切分。保留原句、数字、来源和限定条件。
- **强调要能帮助扫读。** 加粗用于结论、关键概念或操作中的关键条件，优先选短语或短句。同一段避免整段加粗、连续多处强调，避免同时叠加加粗、底色、下划线和颜色。已存在的强调先判断作用再保留或调整，不以“加粗数量”作为完成标准。
- **高亮有独立含义。** 普通 `**加粗**` 只加粗；确需底色时显式使用 `<mark>文字</mark>`。下划线通常留给链接；不要用下划线装饰普通正文。中文正文不依赖斜体承担关键强调。
- **换行表达作者意图。** 源文件中的普通单次折行仍属于同一段；空行产生新段落；行末两个空格、反斜线或 `<br>` 表示明确换行。步骤、列表使用对应 Markdown 结构，不用空格模拟缩进，不用连续 `<br>` 撑出空白。
- **标题反映真实层级。** 正文小标题以 `##`、`###` 为主，避免跳级和密集小标题。现有 H1 与 frontmatter 不因纯排版自动删除或改写。用户明确指定或锁定的标题原样保留；图注、引用及用户删除过的内容不擅自补回。
- **图片与说明保持对应。** 原图顺序不变，图注紧随对应图片。截图中的文字必须在手机宽度下检查；信息图不能为填满框而裁掉内容。

验收时先扫读标题与强调，确认能抓到主线；再按 360px 手机宽度通读，检查段落密度、强调是否过密、图片文字和长图衔接。渲染报告中的长段落、强调比例和图片分辨率提示只用于定位问题，不能代替语义判断，也不授权自动改写正文。
