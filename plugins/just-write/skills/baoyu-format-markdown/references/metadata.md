# 元数据准备

仅在发布、独立配文或用户明确要求 frontmatter 时读取。元数据不是排版的默认附加产物。

## 内容与存放

- 唯一现有标题可沿用。frontmatter `title` 与 H1 不同且需要平台标题时，先解决实质冲突，不能自动认定其中一个更好。
- 摘要概括正文已有范围和结论，不补数字、经历、效果或未证实评价。说明性摘要可以直接描述主题，无需强迫“价值钩子”。
- 保留已有可用字段；仅生成当前平台缺少且实际需要的字段，不每次都补 summary 与 description 两份。
- 作者、封面等优先使用已有明确输入；不要从正文猜作者身份。
- 用户保护整稿时，将摘要、标题候选、平台配文写入独立文件，平台 CLI 显式传参，源稿不变。
- 没有保护限制且用户要求 frontmatter 时，字段只承载获准信息，未知键保留。

## 字段用途

| 字段 | 用途 |
|---|---|
| `title` | 文章显示标题；不代表用户已经确认 |
| `summary` | 简短概括，按当前用途决定长度 |
| `description` | 可选的较完整预览描述 |
| `author` | 明确作者名 |
| `coverImage` | 微信封面相对路径或显式资源 |
| `xhsCoverImage` | 独立 XHS 封面；不与微信封面互相替代 |
| `theme / color` | 需要时提供平台排版覆盖值 |

各平台本地限制由对应脚本校验。受保护摘要超限需要调整或用户决定，不静默截断。平台转换可以避免重复显示 H1，但不回写源稿。

摘要为输入已有文本时只核对范围；自行生成时逐项与正文核对。交付中说明独立文件或实际新增字段，不宣称同时完成未请求的平台任务。
