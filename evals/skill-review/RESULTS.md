# Just Write 1.6.0 实施与验收记录

验收日期：2026-10-09。范围为当前仓库、本地文件及模拟平台接口。插件元数据统一为 1.6.0，工作流状态为 schemaVersion 2。

## 实施结果

八个技能名称、六个工作流 mode、文章目录、独立平台封面、抖音配文和既有渲染能力均保留。入口按职责重写，完整规则放入按需读取的参考资料：

- 主技能负责识别当前请求、组合任务、确认点和状态需要；信息充分时直接完成，已授权的自然语言确认继续有效。
- 写作以主张与证据范围判断材料是否充分，取消固定材料数量、亲历、情绪和事件链门槛；同一证据可以支持有效机制解释。
- 共用内容契约保护事实、归因、不确定性、数量限定、原话和用户指定边界。局部润色允许无需修改，主要结构修改才使用完整编辑流程。
- humanizer 只处理可指出的局部表达问题。三步、术语、真实引语、必要标点及总结按功能保留；不以命中清零或模型自评分证明质量。
- 排版、标题与发布元数据分开；纯排版生成衍生稿，不自动扩展到标题、摘要和分析文件。作者画像不会自动创建。
- 微信承担账号、草稿及核验；XHS 交付本地轮播、配文、预览与报告；抖音默认校验，交接和上传必须明确选择执行方式并具有用户授权。

六份原有参考资料完成对应修改；新增内容契约、状态迁移、材料充分性、humanizer 分类/示例/配置、元数据、微信配置与恢复、XHS 渲染参考。示例补入无需修改、保留三步、术语、引语及数量限定的情形。

## 工具与接口

| 模块 | 已实施的行为 |
|---|---|
| 文案检查器 | `--rules / --exemptions / --json`；通用信号只提示，明确作者规则才阻断；有限内置句式 ID；完整术语保护；例外绑定原文 SHA-256 与 UTF-16 区间；退出码 0/1/2，空正文 `scanned:false`；兼容但弃用 `--strict` |
| 状态 v2 | 初始化不冒认完成或确认；标题锁及来源；产物/实际输入哈希和标题依赖；按动作校验；安全相对路径；只读 show；首次写入保留不可覆盖的 v1 备份；历史完成、锁定、平台声明单独保存 |
| 微信 API | 专用命令兼容默认保存草稿；离线 dry-run；明确 save-draft；多账号严格解析与完整凭证来源；草稿 ID 与读回验证分开；未知结果不重复创建；图片上传失败立即停止，避免创建缺图草稿 |
| 微信浏览器 | 默认预填，save-draft 才保存，submit 为别名；只把新的明确保存结果作为回执，任意 toast 不算成功；预填为 manual_handoff |
| 抖音 | 默认零上传调用；dry-run/draft/publish 互斥；交接与上传要求账号；上传器退出 0 没有公开回执仍为 outcome_unknown；中断结果保留未知并清理临时文件；YAML 2.8.2 锁定解析，建议不进入上传载荷 |
| XHS | caption-body-file 在 staging 中形成最终配文，显式空文件也优先；源稿不改；JSON 保留旧顶层字段并追加可登记 result；超限保留旧产物 |
| 上游更新 | 默认获取并记录完整上游 revision，生成差异而不覆盖；支持 skill/ref/输出目录；来源清单如实保留未知历史 revision，记录本地定制和当前许可依据；只清理本次临时目录 |
| 结构与 CI | 校验版本、八个入口、资源、本地引用与七个 CLI 参数契约；Windows/Ubuntu 单元与 CLI 作业，Ubuntu 渲染回归并保留产物；模型对照不进入 CI |

方案中的微信状态枚举漏列了它同时要求记录的 `manual_handoff`，实现补齐该状态。微信 dry-run 记录为状态 `ready` 加最近操作结果 `dry_run`；保存事实不会因核验失败或源稿变化而被抹掉。状态及平台结果限制已知字段，拒绝凭证、聊天记录等不属于状态契约的数据。
